Building an agent

The system prompt is the job description

  bad:  "You are a helpful assistant that
         helps the user with their files."

  good: "You manage files in ~/notes.
         Tools: list_files, read_file.
         Ask before deleting anything.
         If a path is ambiguous, name the
         two options and stop."

The model starts every session knowing nothing about your product, your paths or your rules. The system prompt is the only onboarding it gets — write it like day one for a new hire.

The good version above is specific on purpose: what the job is, which tools exist, where the lines are. Vague instructions produce confident guesses exactly where you left gaps.

Keep it short. Every line you add is also a line the model can get wrong. If a rule matters, one plain sentence beats three paragraphs of nuance.
