Building an agent

Test your agent like software

  vibes testing:              fixed cases:
  "hmm, feels better?"        list of 20 inputs
                                → expected tool + args
  change the prompt           run all 20
  hope                        18 pass, 2 fail
        |                              |
        v                              v
  the bug is still there      the bug has a name

Every prompt tweak, model swap or new tool changes behaviour everywhere at once. Without fixed cases you can only see the change you were looking for.

A case is just: this input → this tool call with these arguments. No judge model, no vibes. Twenty of them live in a file you can run before every deploy.

That isn't a test of the answer's quality — that's the model's job. It tests your part: the wiring, the descriptions, the loop.
