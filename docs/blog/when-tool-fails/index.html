Building an agent

When a tool call fails

  your code:  run_tool(...)
        |
        +-- ok      → paste the output back
        |
        +-- error   → paste the error back
                          ("PermissionError: /tmp/log")

  what NOT to do:
      catch it silently
      return "" or "success"
      → the agent keeps building on nothing

An error message is not a failure of the loop — it's information. Paste the real error back and the model will often fix its own call: wrong path, missing arg, wrong order.

The failure mode that hurts is swallowing it. If your code returns an empty string on error, the agent reads that as success and builds the next three steps on a hole.

Retry the ones worth retrying (timeouts, rate limits) with a short backoff. Never retry what the model can't change, like a missing file — let it read the error and pick a new move.
